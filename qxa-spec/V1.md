# QXA V1 — Cryptographically Serialized Assets on Bitcoin

## 1. Overview

QXA is a Bitcoin-native asset issuance protocol where **each unit is created by the irreversible consumption of one XMSS signing state**, then **ownership is tracked via Bitcoin UTXOs** (with indexer-maintained serial ↔ outpoint mapping).

This is structurally different from balance-based protocols (e.g. BRC-20, Runes): there is no `mint amount`. There is only **serial #N** born with a **PQ issuance proof**.

## 2. Design boundaries

- Bitcoin consensus does **not** verify XMSS. Taproot remains BIP-340 Schnorr.
- V1 relies on: **Bitcoin** (settlement + DA), **XMSS** (issuance), **Indexer** (protocol rules).
- `2^h` capacity applies **per Genesis root**, not globally. A new root defines a **new AssetID**; it cannot extend another asset's supply.

## 3. AssetID

```
AssetID = SHA256(
    "PQASSET/V1"
    || genesis_outpoint (36 bytes: txid LE + vout u32 LE)
    || xmss_public_root (n bytes, from normalized XMSS public key)
)
```

`xmss_public_root` is the Merkle root field in the XMSS public key (see `qxa-crypto::xmss_root`).

## 4. Tagged hashing

All protocol digests use BIP-340-style tagged SHA256:

```
TaggedHash(tag, msg) = SHA256( SHA256(tag) || SHA256(tag) || msg )
```

Tags are UTF-8 strings without a null terminator.

## 5. Operations

Magic: `QXA` (`0x51 0x58 0x41`). Version: `0x01`.

| Opcode | Name | Purpose |
|--------|------|---------|
| `0x01` | GENESIS | Define an issuance domain |
| `0x02` | ISSUE | Birth one serial via XMSS |
| `0x03` | TRANSFER | Move ownership (no PQ sig) |
| `0x04` | CLOSE | Permanently stop issuance |

### 5.1 GENESIS

Off-chain / witness payload (canonical binary, big-endian unless noted):

| Field | Size | Description |
|-------|------|-------------|
| magic | 3 | `QXA` |
| version | 1 | `0x01` |
| operation | 1 | `0x01` |
| parameter_set_id | 2 | Registry id (see `qxa-crypto`) |
| tree_height | 1 | Must match parameter set |
| xmss_public_root | n | Root bytes |
| symbol | 4–12 | UTF-8, padded with `0x00` to 12 bytes |
| metadata_hash | 32 | `SHA256(metadata.json)` |
| issuance_policy | 1 | `0x00` SEQUENTIAL_ISSUER, `0x01` BLOCK_LOTTERY_V1 |

On-chain: commit `SHA256(genesis_payload)` via Taproot witness envelope or `OP_RETURN` (implementation profile).

Indexer creates asset record:

- `next_index = 0`, `issued = 0`, `closed = false`
- `max_serials = 2^tree_height` (from approved parameter set, not arbitrary)

### 5.2 ISSUE

Canonical message signed by XMSS:

```
M = TaggedHash(
    "QXA/ISSUE",
    AssetID
    || uint64_be(serial)
    || recipient_script_pubkey (normalized)
    || genesis_outpoint (36 bytes)
    || uint64_be(nonce)
)
```

Validation (indexer):

1. Asset exists and not `closed`
2. `serial == next_index` (strict sequential issuance in V1)
3. `serial` never previously issued
4. XMSS verify against genesis public key / root
5. Bitcoin tx assigns `recipient_script_pubkey` to `recipient_vout`
6. Confirmation depth ≥ policy threshold

On success: `issued += 1`, `next_index = serial + 1`, record birth outpoint.

**Reorg:** If the Bitcoin birth tx is reverted, indexer rolls back issuance **but the XMSS index remains burned** — index MUST NOT be re-signed.

### 5.3 TRANSFER

No XMSS. Spend current asset UTXO; commitment:

```
operation = TRANSFER
AssetID
uint64_be(serial) OR range (see §6)
uint32_be(destination_vout)
```

Indexer moves ownership to new outpoint when spend is confirmed.

### 5.4 CLOSE

Issuer-signed Bitcoin message (no new XMSS index). Sets `closed = true`; further ISSUE invalid.

## 6. Serial ranges

Balances are stored as inclusive ranges:

```
{ asset_id, range_start, range_end, outpoint }
```

Transfer may split/merge ranges. Collectible singles (e.g. `#0`) are ranges with `start == end`.

## 7. Fair launch — BLOCK_LOTTERY_V1

Genesis `issuance_policy = BLOCK_LOTTERY_V1`.

Claim in block `N`:

```
CLAIM { AssetID, claimant_script_pubkey, commitment }
```

After block `N+1` is known:

```
score = SHA256( block_hash(N+1) || claimant_outpoint )
```

Lowest score wins the next serial (batch extensions: top-K per block per §12 of product spec).

Issuer MUST sign ISSUE for the winner's script. Valid XMSS sig to wrong recipient → **INVALID**.

## 8. Reorg semantics

Every mutation records: `block_height`, `block_hash`, `tx_index`, `event_index`.

On reorg: rollback events above common ancestor, replay forward.

Signer state is **monotonic** and never decreases index on Bitcoin reorg.

## 9. Witness profiles

| Profile | PQ signature | Notes |
|---------|--------------|-------|
| `WITNESS_FULL` | Full detached sig in tapscript witness | Preferred for signet |
| `HASH_COMMIT` | `SHA256(full_issue_proof)` on-chain | Full proof on DA layer |

Indexers MUST support `WITNESS_FULL` for V1 interop tests.

## 10. Reference code

- `qxa-signer` — atomic XMSS state
